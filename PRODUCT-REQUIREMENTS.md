# Требования к продукту agentic-report

Этот документ определяет поддерживаемый продуктовый контракт. `agentic-report` — локальный инструмент, с
помощью которого программный агент создаёт интерактивную браузерную страницу из компактного декларативного
источника.

## Продукт

- **`AR-PRODUCT-FOCUS` — Интерактивные страницы для агентов.** Агент описывает содержание, структуру,
  оформление и интерактивные блоки на уровне смысловых примитивов, не собирая каждый раз отдельное
  приложение вручную.
- **`AR-PRODUCT-LOCAL` — Локальная генерация.** CLI и программный API читают локальный проект и создают
  готовую браузерную страницу без облачного сервиса продукта.
- **`AR-PRODUCT-DELIVERY` — npm CLI и ESM API.** Пакет предоставляет исполняемую команду, строгие
  TypeScript-типы и программный интерфейс для вызова из агента или локального инструментария.
- **`AR-PRODUCT-USE-CASES` — Типовые страницы.** Поддерживаются отчёты об исследовании и работе,
  архитектурные обзоры, руководства, dashboards, страницы решений и лендинги.
- **`AR-PRODUCT-PUBLIC-PROOF` — Публичное доказательство продуктом.** Публичный лендинг собирается самим
  `agentic-report` из обычного декларативного источника. Он ведёт на три отдельно опубликованных вымышленных
  демо-страницы — incident review, vendor decision и launch readiness — и на публичный Markdown-исходник
  каждой страницы. Скриншот служит превью, но не заменяет доступное интерактивное демо.
- **`AR-PRODUCT-COMPLETE` — Готовый продукт.** Итог включает удобное создание проекта, сборку,
  компоненты, шаблоны, примеры, документацию, тестируемый npm-пакет и подготовленный выпуск.
- **`AR-PRODUCT-MOIRA-ATTRIBUTION` — Публичная обратная ссылка.** Внизу README, который показывают
  GitHub и npm, и каждой опубликованной HTML-страницы продуктового сайта находится компактная плашка
  `Made with Moira`, ведущая на `https://moira-mcp.com/`. Это оформление публичных каналов
  `agentic-report`, а не функция компилятора: плашка не добавляется в страницы пользователей.

## Авторский опыт агента

- **`AR-AUTHOR-MARKDOWN` — Markdown как основа.** Основной текст остаётся обычным Markdown.
- **`AR-AUTHOR-MANIFEST` — Декларативная конфигурация.** Настройки страницы, темы, навигации, данных и
  компонентов задаются в YAML frontmatter либо YAML/JSON manifest.
- **`AR-AUTHOR-PARTIALS` — Композиция.** Большая страница разбивается на локальные Markdown partials и
  переиспользуемые декларативные фрагменты.
- **`AR-AUTHOR-ASSETS` — Локальные ресурсы.** Страница может включать изображения, шрифты и файлы из
  корня проекта.
- **`AR-AUTHOR-NO-JSX` — Без обязательного JSX.** Типовой агентский сценарий не требует React, JSX,
  ручной DOM-разметки или знания внутреннего Vite-проекта.
- **`AR-AUTHOR-ERGONOMICS` — Короткий путь.** Команды `init`, `validate`, `inspect` и `build` дают агенту
  предсказуемый цикл: создать основу, заполнить её, получить точные ошибки и собрать результат.
- **`AR-AUTHOR-INIT-NEW` — Только новый проект.** `init` принимает только отсутствующий путь назначения.
  Любой существующий файл или каталог, включая пустой, приводит к ошибке. Команда никогда не удаляет и не
  откатывает содержимое пути назначения; непосредственный родитель должен быть существующим обычным
  каталогом. Это исключает скрытую файловую транзакцию и создание неявной цепочки каталогов из авторского
  сценария.
- **`AR-AUTHOR-DISCOVERY` — Машиночитаемый каталог.** CLI и API перечисляют доступные шаблоны, темы,
  компоненты, их свойства, значения по умолчанию и короткие примеры.
- **`AR-AUTHOR-DIAGNOSTICS` — Исправимые ошибки.** Диагностика содержит стабильный код, путь, диапазон,
  понятное сообщение и подсказку без утечки содержимого файлов или credentials.
- **`AR-AUTHOR-TIME-TEXT` — Время остаётся текстом.** Обычные записи времени суток, диапазонов и
  длительностей (`21:01`, `21:01 — 00:12`, `1:30:05`) пишутся в Markdown и frontmatter без экранирования и
  печатаются дословно; это исключение не скрывает неизвестные имена настоящих директив.
- **`AR-AUTHOR-REVIEW-PROTOCOL` — Переносимый review-контракт.** Каждая собранная страница содержит
  ограниченный детерминированный каталог смысловых review-целей, привязанный к версии локального графа
  исходников. Закрытый `review.json` версии 2 хранит треды с упорядоченными сообщениями пользователя и
  агента и состоянием resolved без выполнения авторского кода.
- **`AR-AUTHOR-REVIEW-BINDING` — Обратная привязка к Markdown.** CLI и ESM API проверяют локальный
  review-артефакт и связывают треды с точными диапазонами entry или partial. Изменённые, отсутствующие и
  неоднозначные цели не подменяются похожим текстом и возвращаются как отдельные состояния.
- **`AR-AUTHOR-REVIEW-RECONCILIATION` — Повторный цикл ревью.** `build`, `validate` и `inspect` принимают
  один необязательный локальный prior-review sidecar, ограниченный source root, размером и обычным JSON-
  файлом, не совпадающий с исходником или output. Точная ревизия восстанавливает текущее состояние;
  устаревшая показывает отдельные `exact/changed/missing/ambiguous` prior-треды без угадывания похожего
  текста. Продолжение добавляет новый revision-segment в тот же тред и сохраняет прежние сообщения агента,
  пользователя и resolved-state в исходном segment. Ошибка не меняет существующий output и не отравляет исправленный повтор;
  завершённое новое ревью экспортируется для следующей неизменённой сборки без семантического дрейфа.

## Шаблоны и визуальная система

- **`AR-TEMPLATE-STARTERS` — Готовые основы.** Пакет содержит starters для отчёта, исследования,
  архитектурного обзора, руководства, dashboard и landing page.
- **`AR-TEMPLATE-THEMES` — Темы.** Агент выбирает тему и компактно настраивает цветовой акцент,
  плотность, типографику и ширину содержимого без ручного CSS.
- **`AR-TEMPLATE-LAYOUTS` — Компоновки.** Поддерживаются document, dashboard, landing и mixed layouts с
  адаптивной навигацией.
- **`AR-TEMPLATE-CONSISTENCY` — Единый дизайн.** Все встроенные компоненты используют общие токены,
  отступы, состояния и responsive-правила.
- **`AR-TEMPLATE-EXTENSION` — Переиспользуемое расширение.** Новые package-owned шаблоны, темы и
  компоненты добавляются через один типизированный реестр, а не отдельными генераторами.

## Компоненты страницы

- **`AR-COMPONENT-CONTENT` — Контентные блоки.** Заголовки, автоматическая навигация, callout, decision,
  карточки, шаги, таблицы, код, изображения и вложения имеют готовое качественное представление.
- **`AR-COMPONENT-SOURCE-LINK` — Адрес места в коде.** Декларативная ссылка показывает короткий путь и
  строку, открывает полный адрес через явно указанный локальный editor-helper и не заменяет страницу отчёта.
  Компилятор не обращается к helper самостоятельно и не читает указанный им файл. Полный абсолютный путь
  остаётся в HTML, поэтому такая ссылка привязана к рабочей машине и удаляется или заменяется перед публичной
  раздачей, если имена локальных каталогов раскрывать нельзя.
- **`AR-COMPONENT-CODE-GLOSSARY` — Термины в прозе и коде.** Один канонический ключ допускает явно
  размеченную грамматическую форму в прозе и первое точное каноническое вхождение внутри выбранного блока
  кода. Подсветка Shiki, клавиатурное/сенсорное объяснение, ссылка на полное определение и чистое копирование
  кода сохраняются. Определение остаётся на месте по умолчанию или явно переносится в видимый справочный
  appendix вне основной навигации; автоматическое распознавание словоформ не заявляется.
- **`AR-COMPONENT-INTERACTIVE` — Интерактивные блоки.** Tabs, disclosure, modal/popover, фильтры,
  переключатели и ограниченные демонстрации работают через package-owned browser runtime.
- **`AR-COMPONENT-COPYABLE-PROSE` — Копируемая проза.** Обычный Markdown-блок сохраняет пропорциональный
  шрифт и перенос строк, но получает локализованную keyboard-доступную кнопку; в буфер попадает только
  видимый текст без Markdown/HTML, package controls и скрытых объяснений.
- **`AR-COMPONENT-DATA` — Данные и визуализации.** Диаграммы и графики принимают ограниченные
  декларативные данные. Flow-схема поддерживает до двадцати узлов и два-три именованных subsystem group;
  sequence-схема сохраняет авторский порядок участников и сообщений. Обе формы компилируются в
  детерминированный доступный SVG без browser renderer, сети или внешнего graph DSL.
- **`AR-COMPONENT-STATE` — Предсказуемое состояние.** Компоненты имеют документированные начальные
  состояния, события и ограничения; авторский Markdown не исполняет произвольный код.
- **`AR-COMPONENT-ACCESSIBILITY` — Практическая доступность.** Встроенные элементы используют корректную
  семантику, видимый focus и основные keyboard/touch-маршруты. Доступность проверяется обычными unit/E2E
  тестами и не требует отдельной формальной исследовательской программы.
- **`AR-COMPONENT-RESPONSIVE` — Desktop и mobile.** Страница и все starters пригодны для обычных
  desktop- и mobile-размеров без горизонтального разрушения основной компоновки.
- **`AR-COMPONENT-LOCALIZATION` — Язык интерфейса читателя.** Значение `language` из входного manifest
  детерминированно выбирает один полный package-owned каталог интерфейса. Русский (`ru` и его subtags)
  локализует оболочку, интерактивные состояния, доступные имена, визуализации и Review Workspace;
  английский, `und` и неподдерживаемые языки используют полный английский fallback независимо от языка
  браузера. Авторский Markdown и CLI-диагностика не переводятся.
- **`AR-COMPONENT-REVIEW-WORKSPACE` — Локальные треды ревью.** Обычная страница открывается в чистом режиме
  чтения. Человек явно включает Review Workspace, открывает тред у конкретного фрагмента, накапливает и
  редактирует сообщения, видит отдельные ответы агента и отмечает тред resolved или reopened. Компактный
  индикатор у фрагмента открывает обсуждение, все треды импортируются или экспортируются одним
  детерминированным `review.json`. Desktop использует немодальную боковую панель, mobile — нативный модальный
  sheet с корректным focus return. Формальные verdict, approval gate и review-чек-листы не входят в этот UX.
- **`AR-COMPONENT-RESPONSE-WORKSPACE` — Структурированный ответ читателя.** Декларативная форма поддерживает
  раскладывание пунктов по двум–пяти корзинам, один или несколько вариантов на пункт, один вариант на весь
  вопрос, порядок пунктов, ограниченные числовые оценки, общий свободный текст и необязательные комментарии
  к отдельным пунктам. Пункт сохраняет заголовок, пояснение, метаданные и безопасную ссылку на оригинал.
  Ответ полностью вводится с клавиатуры; drag-and-drop для корзин остаётся дополнительным pointer-маршрутом.
- **`AR-AUTHOR-RESPONSE-PROTOCOL` — Переносимый response-контракт.** Страница экспортирует одно и то же
  каноническое JSON-состояние в буфер и в локальный файл. Каждый вопрос хранит вид, явный признак ответа и
  машиночитаемое значение; непустые item-комментарии лежат отдельно. Form revision, закрытая схема и
  validate-before-swap import не дают чужому, устаревшему или повреждённому файлу затереть текущие ответы.
  Состояние существует только в текущей вкладке без сети, аккаунта, form submission и browser storage.

## Сборка и результат

- **`AR-OUTPUT-SINGLE` — Один файл по умолчанию.** Обычная сборка создаёт автономный HTML с встроенными
  стилями, package-owned runtime и подходящими локальными ресурсами.
- **`AR-OUTPUT-DIRECTORY` — Каталог при необходимости.** Для больших страниц доступен `index.html` с
  content-hashed ресурсами.
- **`AR-OUTPUT-RUNTIME` — Один поддерживаемый runtime-профиль.** Интерактивность является частью
  продукта. Режимы `scripts:none`, JavaScript-disabled parity и runtime-failure fallback не поддерживаются
  и не являются release-гейтами.
- **`AR-OUTPUT-FILE-URL` — Простое открытие.** Готовый артефакт открывается через `file://` без запуска
  сервера. Это требование относится к нормальному интерактивному режиму с JavaScript.
- **`AR-OUTPUT-DETERMINISTIC` — Повторяемость.** Одинаковые входы и версии инструмента дают одинаковые
  выходные байты, кроме явно документированных полей.
- **`AR-OUTPUT-SAFE-WRITE` — Безопасная публикация.** Сборка не перезаписывает исходники и не оставляет
  ложный частичный результат при ошибке.

## Безопасность и архитектура

- **`AR-SECURITY-CONFINEMENT` — Корень проекта.** Все локальные ссылки разрешаются и проверяются внутри
  канонического source root до чтения.
- **`AR-SECURITY-SOURCE` — Без неявного авторского выполнения.** Markdown, manifest и partials не
  запускают произвольный код. Расширение исполняемого поведения требует отдельного явного product API.
- **`AR-SECURITY-RUNTIME` — Package-owned runtime.** В итоговую страницу попадает только runtime,
  собранный и поставленный пакетом, плюс проверенные декларативные данные.
- **`AR-SECURITY-REDACTION` — Безопасный транспорт.** Human/JSON/NDJSON-вывод не включает credentials и
  полные исходные тексты.
- **`AR-SECURITY-REVIEW` — Ограниченный локальный review.** Review-файл читается только внутри
  канонического source root, имеет закрытую версионированную схему и размерные ограничения. Транспорт
  возвращает только ограниченные структурированные поля, точные координаты и централизованно очищенный
  поля тредов и сообщений, но не выгружает исходный или review-файл целиком.
- **`AR-ARCH-SEPARATION` — Независимые границы.** Загрузка источника, модель страницы, компоненты,
  ресурсы, рендеринг, публикация, CLI/API и browser runtime тестируются независимо.
- **`AR-ARCH-STRICT` — Строгий TypeScript.** Код не использует `any` и не ослабляет compiler/lint rules.
- **`AR-ARCH-REUSE` — Переиспользование перед bespoke.** Перед добавлением крупного примитива проводится
  короткий spike существующих решений. Исследование ограничено решением конкретного выбора и не блокирует
  реализацию многократными формальными review-циклами.
- **`AR-ARCH-PROPORTIONATE` — Простая файловая модель.** Продукт не реализует собственную транзакционную
  файловую систему, inode-ledger или защиту от враждебной одновременной подмены путей. Безопасность `init`
  обеспечивается отказом для существующего назначения, эксклюзивным созданием нового каталога и отсутствием
  удаления из него при ошибке.

## Качество и выпуск

- **`AR-QUALITY-UNIT` — Unit-тесты.** Покрываются схемы, source graph, компоненты, ресурсы, диагностика и
  безопасность путей.
- **`AR-QUALITY-E2E` — Браузерные тесты.** Основные starters и интерактивные компоненты проверяются в
  Chromium на desktop и mobile через реальные собранные `file://`-артефакты.
- **`AR-QUALITY-PACKAGE` — Реальный consumer.** Проверка создаёт npm tarball, устанавливает его в чистый
  проект и запускает CLI и ESM API без доступа к рабочему дереву.
- **`AR-QUALITY-SCOPE` — Пропорциональная проверка.** Тест доказывает наблюдаемое поведение продукта.
  Искусственные proof-ledgers, десятки тысяч неисполняемых будущих ячеек и повторные immutable протоколы
  не являются продуктовым результатом.
- **`AR-RELEASE-FIRST-USE` — Первый результат.** Новый агент устанавливает пакет, выбирает starter,
  изменяет содержимое и одной командой получает качественную интерактивную страницу.
- **`AR-RELEASE-NO-BLOCKERS` — Готовность.** Все перечисленные здесь требования реализованы, основные
  сценарии проходят, npm-артефакт проверен, а известных блокирующих дефектов нет.

## Явно исключено

Следующее не входит в продукт и не должно создавать задачи, бюджеты или release-гейты:

- печать, PDF, пагинация и проверка печатных профилей;
- работа страницы при отключённом JavaScript;
- `scripts:none` и матрицы отсутствующего/повреждённого runtime;
- обязательные текстовые или табличные fallbacks для интерактивных визуализаций;
- формальная верификация browser telemetry, браузерного Find UI и доказательной неподделываемости;
- исчерпывающие матрицы всех браузеров, assistive technologies, output/script policies и искусственных
  boundary-комбинаций;
- облачный backend, hosted editor и collaboration service; статическая публикация продуктового лендинга,
  демо и документации является каналом распространения, а не hosted-режимом компилятора;
- произвольный raw HTML и выполнение JavaScript непосредственно из Markdown по умолчанию.
