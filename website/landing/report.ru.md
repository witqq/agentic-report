# Дайте агенту лучший способ передать результат.

**Декларативные страницы для передачи результатов агента**

Установите один навык. Ваш агент разработки сможет превращать исследования, экскурсии по коду, решения,
инциденты и статусы в качественную интерактивную страницу, когда визуальная структура помогает пониманию.
Всё остаётся локальным; отдельный фронтенд-проект не нужен.

должны перепроверяться, а хешированные ресурсы каталога можно неизменно кешировать год.

:::callout{kind="info" title="Когда стоит создать страницу"}
Используйте её, когда обычный ответ в чате скроет связи или усложнит ревью: несколько выводов с данными,
путь по коду с определениями, конкурирующие варианты и условия, хронология, панель, учебный материал или
передача с комментариями к точным фрагментам. Простые ответы оставляйте в чате; для живых вычислений
используйте блокнот, а для постоянного многопользовательского состояния — отдельное приложение.
:::

:::::section{title="От пустого каталога до страницы для ревью." id="workflow" nav="Рабочий процесс" width="standard" align="start" tone="plain"}
Используйте Node.js 24.18.0 или новее. Первому запуску `npx` нужны реестр и сеть для загрузки пакета;
компиляция и созданная страница затем работают локально.

:::steps{title="Первый полезный результат"}

1. Создайте проект: `npx --yes agentic-report init ./my-page --starter landing --json`.
2. Измените декларативный Markdown и добавляйте только ограниченные части или локальные ресурсы.
3. Запустите `npx --yes agentic-report validate ./my-page --json`; исправьте все нарушения вместе.
4. Примените точные вычисленные исправления через `npx --yes agentic-report fix ./my-page`, затем запустите `inspect`.
5. Выполните `npx --yes agentic-report build ./my-page --output ./my-page.html --json` и откройте результат через `file://`.
   :::

:::callout{kind="info" title="Диагностика для агента, читаемый вид по запросу"}
Все девять команд CLI обнаруживаются машинно. Исполняемые команды по умолчанию возвращают NDJSON, справочные —
одну компактную строку JSON; `--json` явно выбирает этот формат, а `--human` — текст или форматированный JSON.
Один отказанный проход директив возвращает первое авторское нарушение и все независимые в `related`, а зависимости
правил видны через `describe`. Только `fix` изменяет Markdown и применяет точные вычисленные диапазоны. Авторы
глоссария объявляют формы через `forms`; пакет их не угадывает. `init` принимает родителя-символическую ссылку,
например macOS `/tmp`, сообщает разрешённый путь и всё равно отклоняет существующее назначение.
:::

:::callout{kind="success" title="Верните структурированную обратную связь агенту"}
Выделите любой подходящий фрагмент созданной страницы и выберите **Создать заметку**. Привязанное всплывающее
окно показывает точную цитату и позволяет рядом ответить, изменить, закрыть или снова открыть ветку — отдельного
режима ревью и сдвига компоновки нет. Выделение может пересекать встроенную разметку и соседние цели. Сохранённые
открытые и закрытые диапазоны остаются подсвеченными; **Посмотреть обсуждение** вновь открывает разговор, а
**Ревью** показывает только оверлей со списком, прежними данными, импортом и экспортом. На локализованной странице
экспортируйте все ветки в детерминированный `review.json` версии 4 с языком отчёта; одноязычные страницы сохраняют
версию 3. Ветки версии 2 для целого блока остаются доступны в списке, но новые начинаются с выделенного текста.
Ревью остаётся локальным; команда CLI сопоставляет цели с текущими диапазонами Markdown или его частей. Один
артефакт поддерживает до 5 000 целей ревью и манифест целей до 750 000 байт; разделите необычно большую передачу
при достижении любого ограничения. [Попробовать заметки к выделению](examples/review-workspace/index.html).
:::

:::callout{kind="info" title="Соберите структурированное решение, когда комментариев недостаточно"}
Response Workspace добавляет ограниченную сортировку по корзинам, варианты для пунктов и всей формы,
порядок приоритетов, оценки, свободный текст и необязательные комментарии. Ответы остаются в текущем языке
и вкладке, импорт проверяется до замены состояния, а буфер и файл получают один детерминированный
`response.json`. [Попробовать двуязычную форму](examples/response-workspace/index.html),
[прочитать английский исходник](examples/response-workspace/report.md) или
[прочитать русский исходник](examples/response-workspace/report.ru.md).
:::

:::callout{kind="warning" title="Среда выполнения — часть артефакта"}
Авторы не пишут браузерный JavaScript, но обычные созданные страницы интерактивны и требуют среду из пакета.
Профили с отключённым JavaScript или отказом среды не входят в продукт.
:::

:::::section{title="Знайте возможности и границы." id="boundaries" nav="Границы" width="standard" align="start" tone="plain"}
::::cards
:::card{title="Входит"}

- локальный декларативный компилятор;
- ограниченные Markdown, части и локальные ресурсы;
- девять обнаруживаемых команд CLI с JSON/NDJSON для агента по умолчанию и представлениями `--human`;
- диагностика нескольких нарушений и точное добровольное исправление Markdown через `fix`;
- обязательная интерактивная среда выполнения из пакета;
- по умолчанию один файл и необязательный каталог.
  :::
  :::card{title="Не входит"}
- облачный редактор, серверная часть или сервис совместной работы;
- развёртывание или управление учётными записями;
- произвольные авторские HTML, JSX, CSS или браузерный JavaScript;
- удалённая загрузка исходников, ресурсов, скриптов, шрифтов или стилей;
- печать или эквивалентность при отключённом JavaScript.
  :::
